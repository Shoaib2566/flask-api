If the test job fails, the build-docker job will not run because the workflow uses "needs: test".

This means the build-docker job depends on the test job. If the test job fails, GitHub Actions stops the pipeline and does not continue to the Docker build step.

This is important because it prevents broken or untested code from being packaged into a Docker image. It ensures that only code that passes all tests is built and deployed, which improves reliability and saves time and resources.
